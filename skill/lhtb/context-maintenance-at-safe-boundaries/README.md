# Context maintenance at safe boundaries

Derived from the long-task execution and checkpoint stages of two LHTB Claude Code audits: native vs a CLM-enabled adapter without reminders, then one CLM editor with crossing-only vs every-normal-request cues. The second comparison demonstrates adoption sensitivity, not that high-frequency editing improves performance. The five source tasks are discovery examples, not held-out validation. This skill is a candidate, not a measured score improvement.

Use it with native compaction, actor-controlled editing, or workspace checkpoints. Adapt the edit/receipt route to the runtime without changing the safety decision. Keep the short action rules in [SKILL.md](SKILL.md); the evidence and offline tests in [validation](references/validation.md) need not be loaded repeatedly during work.
