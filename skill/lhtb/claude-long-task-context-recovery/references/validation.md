# Validate recovery before adoption

| Fixture | Expected demonstration |
|---|---|
| Long tool output contains a late-use literal | Recover the verified exact value after a supported boundary from a scoped note or tested pointer. Do not infer it from the current prompt. |
| Transcript resumes under the same session ID but a process lost its state | Notice via a minimal health/state probe and restore only from a verified source. Do not report that the task itself persisted. |
| A new spec supersedes a limit for only one target or version | Apply the new value only in scope. Preserve the original evidence and check a historically scoped query. |
| An edit is queued but not applied; or there are no safe candidates | Do not report an applied edit. Leave a documented no-op or recover from a known checkpoint. |
| A local test summary says pass but the verifier or live artifact says otherwise | Record the test inputs and disagreement; base continuation on current verified evidence, not the summary label. |

In a controlled test, use clones of a frozen boundary with the same task, model, budget and verifier. Compare artifact-only recovery with artifact plus checkpoint; if testing editing, match the prompt, exposure and runtime, then compare no-op, selective deletion and deletion with a scoped note. Keep default fallback, invalid attempts and early stops visible. Measure resumed state, first substantive action, unnecessary rereads, real applied edits, input/cache/output, and actual outcome separately. Do not run the study from these instructions unless explicitly authorized.
