# Codex CLM: make one recoverable, verified edit

## Check applicability and timing
Name the pressure and next decision. If only a skill path is offered and this trigger applies, read the target version first; do not reread a body already in effective context. Keep model-visible input, durable memory and execution evidence distinct. Never rewrite raw execution records to simulate context editing.

Prefer elective edits after delivery and all tools have settled, or before the next task reads materials or makes its first substantive call. A plan or near-final reply is not completion. Normal tools and short task-local notes remain allowed. Mid-task editing is only for approaching capacity, imminent critical-state loss, or inability to continue; make the smallest reversible intervention and resume.

## Inspect and select
Inspect the live contract, revision, byte/token units, protected boundaries, and note replacement versus append behavior. Select structured fields for revision, edit/application state and protections; do not cut the first N characters or interpret absent fields as no event. Without a clear interface, use a native checkpoint, not guessed commands.

Classify content: **keep** exact constraints, unresolved actions, fresh receipts and irrecoverable evidence; **index** retrievable bulky evidence with scope/version/locator; **omit** completed duplicates. Verify recovery from the resuming environment before dropping anything. No recoverable copy means no deletion. Give task-specific notes a narrow scope and exit/invalidation condition.

## Save, edit, verify
Save the prior note and a checkpoint containing entity/version, hard constraints, verified versus attempted state, unresolved side effects, evidence locators and the next check. Confirm the rollback pointer works. A whole-note replacement must retain still-valid old content; omission is not preservation.

Submit one semantic edit using fresh IDs and preserve active tool-call/result pairs. Distinguish proposed, queued, applied and verified. A status call in the same batch as submission may still show the old state. At the applying request, verify revision and actual note/projection before substantive continuation; if unobservable, say so. If safe boundary verification is unavailable, defer elective edits. After rejection, refresh state and diagnose before retrying. After information loss, stop pruning and recover from verified sources.

## Reuse and improve
Retrieve by scope, entity and version. Replace invalidated active memory while retaining provenance; skip inapplicable memory; retain temporarily blocked knowledge with its dependency. Resolve genuine conflicts by the smallest distinguishing check. Recheck changed versions and permissions. Confirm critical retained state supports the next action, not merely that an edit was accepted.

Record offered guidance, body exposure, applicability, action, confirmation and outcome separately. Keep native compaction distinct from CLM edits and cumulative projection differences distinct from single-edit savings. Revise only the failed link; accepted edits or higher scores alone prove no benefit.

Example: replace a completed diagnostic dump with a tested revision-pinned locator, but retain an unresolved action exactly until its receipt is checked.
