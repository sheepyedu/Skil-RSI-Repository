# 编辑失败后重建文件状态

> 状态：初始候选 skill（v0.1）。来自 200 题次轨迹的观察性分析，尚未通过消融或留出测试验证收益。

## 触发条件

Edit 返回未读文件、旧文本不匹配、路径不一致，或压缩后要修改笔记时。

## 执行步骤

1. 先辨认报错类型并确认目标路径、当前环境与文件是否存在；失败调用不计作成功落盘。
2. Read 目标的实际内容，获取包含身份/标题和待改文本的最小充分窗口。
3. 使用真实、唯一且足够短的锚点做局部 Edit；锚点有多个匹配时先缩小范围或补上下文。
4. 检查工具成功回执；重要修改回读确认，并保留无关内容。失败时重新定位，不原样无限重试。

## 注意事项

不要为了消除报错而用全文 Write 覆盖旧知识。未读报错与压缩同时出现，不代表已经证实内部原因。

## 完成检查

- 已按上述步骤处理当前事件，且来源、范围与未确定事项可追溯。
- 没有把失败的工具调用当成已生效修改，也没有把关联当作因果收益。

## 验证指标

修改成功率、重试次数、误删条目数、恢复工具调用和 token 成本。

## 来源与使用边界

来源：本仓库两种任务顺序的 100 题 × 2 次执行及 19 次原生压缩分析。此文件只提供可迁移的操作策略，不包含具体评测题答案。按需读取，不必每轮全量注入；不改变现有工具权限或原生压缩机制。
