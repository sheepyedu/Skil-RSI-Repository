# 验证后再升级

1. **生成。** 打开留出任务族之前冻结规则和版本，明确证据、作用域和轨迹验收条件。不要看完留出分数才挑规则或停止点。
2. **使用。** 离线样例至少包含：①已验证可替代输出与可用的准确指针；②仍依赖原文或来源即将过期，正确做法是保留或存副本；③两个都能读的同名文件，但各自有不同证据；④局部规则修订后，变更和未变更范围各需完成实质动作。合理不编辑可以通过。若当下的来源也能直接推出正确值，仅答对不能证明复用了记忆。
3. **反馈。** 记录是否适合编辑、提示实际发送、提议、生效、行动前的真实输入、正确证据读取、首个决定性动作、独立产物验收、恢复返工及成本。没记录就标未知。原生压缩、当前投影长度、累计命中/未命中和输出分开统计。把匹配的案例、保持不动和失败都纳入结果。
4. **修订。** 提醒过于频繁就收窄边界；指针错误就修类型、范围和版本；输入确认有编辑结果但行动仍错，则分别看检索和决策。旧事实在有效历史范围中保留。用预先定义的行为验收，核对任务要求与被评产物版本；不要把模型自报通过当证据。
5. **可选因果试验。** 同编辑器、同机会下用等长中性提示对状态提示，测试采用率。单独试验某次精确投影：从验证过的同一环境恢复，保持模型、工具和续跑预算一致，比较应用和不应用。用重复配对再估计效果；一对脚本只验证装置。不做隐式裁剪；只有原始与编辑上下文都够用时，才在两边同时关掉后续压缩。

参考：[Anthropic 上下文工程](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)；[StateComp](https://arxiv.org/html/2609.27298v1#S3) 用当时证据定义可编辑条件；[PAIR](https://arxiv.org/html/2609.36526v1#S3) 区分替换效果和触发；[ReScopeBench](https://arxiv.org/html/2611.05450v1#A4.SS1) 检查局部修订后的实际使用。以上用于设计检验，不代表本技能已被证明有效。
