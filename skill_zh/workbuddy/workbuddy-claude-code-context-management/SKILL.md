# 原生 Claude Code：让下一步能够恢复

只留下足以安全做出下一步判断的检查点。会话原始记录、任务检查点和长期项目记忆有不同的生命周期。不因为进入新一轮就写笔记。

## 控制工具返回的内容

- 先明确要做什么决定，再读取对应文件片段、有限的日志末尾、结果计数或失败断言，不整段倾倒。会改变下一步判断的条款、约束或错误字段保留原样。大证据只转存到获准的位置，留下作用域、版本和可回查定位。
- 接近压缩或中断时，记录当前目标和禁止项、工作区和版本、最后核验的状态、未决操作，以及一个下一步和它的验收办法。区分**已起草、已尝试、已核验、受阻**。只写到获准位置并回读；无法跨边界保留时，直接交接关键信息。
- 仅在当前运行环境确实支持且获准时使用上下文诊断或定向压缩；不要假设交互命令是模型可以调用的工具。如果下一份大输出会立即填满窗口，先改读取方式，不要反复压缩。

## 恢复靠查状态，不靠相信摘要

1. 对齐当前任务、工作区和版本。读检查点，再从实时产物或权威来源核验一个足以定论的事实。重复操作前先查已有回执或部分结果。
2. 旧规则和当前证据冲突时，先比作用域、版本和生效时间，再采用当前适用的原始来源。已替代的规则从活动记忆移出；对解释过去决定有用的，保留定位。仍有冲突就写复查条件，不把任务结果、权限、临时路径默认继承到新任务。
3. 在正确的层级核验完成。查看实际产物、完成回执和相关测试。成功的模型响应、行动计划或语法检查，不代表产物已经改变或行为测试已过。验证器根本没运行时，标记为未能验证，不当作实现已经失败。产物一改，受影响的旧验证就必须复验。
4. 只修订出问题的那一项。分清证据没记、读不到、已过期、没用上，还是用了但理解错。只有能说明可重复用途、适用范围、来源和失效条件，才提升为项目记忆。单题进度留在检查点。

例：交接写着“报告已保存并验证”，恢复后却是另一版本。检查准确产物并重新做受影响的验收；旧回执留作历史，不直接重传，也不宣称新版已过验证。
