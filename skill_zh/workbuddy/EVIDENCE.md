# WorkBuddy 逐对轨迹审阅

仅供离线复查。不得把本页或底层题目放进技能评测的运行时检索范围。

## 范围与方法

审阅最终 Codex WorkBuddy 的 65 个完整配对（130 条计分轨迹），来自同一个固定顺序。按入选位置、任务身份和官方指令绑定对齐，查原始事件时间线，不只看分数。审查用户指令、已完成的模型与工具事件、相关读写回执、编辑和压缩；安全类只看上下文管理元数据。未逐字阅读每段流式增量，也没有重跑每个工作区产物。下文位置及实验臂对应最终归档的 `results/native-task-binding.json`；未特别注明时，行号指该绑定的 `agent/native.jsonl`。

分开判定：**生成**笔记/检查点 → **检索到并可见** → **用于**决定或行动 → **核验**效果或失败 → **修订**条目。列目录不算检索到内容；工具回显笔记不代表采取了对应行动；局部验证不等于官方验收。单题内部修复也不足以证明跨任务的学习闭环。

## 哪些发现改变了技能写法

- **保留验证范围，不只保留“已通过”。** 第 23 题 CLM 第 196、301、365、391 行：修改使之前通过的测试失效，需要修复再跑。第 28 题原生第 316、330、389 行：通过未改基线区分原有故障和新改动。CLM 的更大全绿本地测试并未取得更高官方分数。应把验证绑定到版本，不是要求每次跑全量测试。
- **原生压缩是恢复边界，不是结果诊断。** 原生第 31 题第 168 行有题中压缩，后续任务仍能读当前证据。CLM 第 25、30、36 题开题前发生保护性压缩，之后有领先也有落后。不能因为是 CLM 实验臂，就认为每题都有模型主动编辑。
- **意识到无关不等于退役旧记忆。** 第 36 题 CLM 第 80、125 行显示模型看到旧笔记并判断它无关；第 43 题第 48 行仍能看到。应增加作用域和过期检查，但没有证据说旧笔记导致失败。
- **入队不是应用。** 第 1 题 CLM 累计会话第 66–69 行显示刚提交后的状态仍无已接受编辑；下一次网络请求（00010）的回执才记录接受。后续多次状态查看只截了前面字符，可能漏掉修订版和接受状态，应按字段查看。
- **已编辑、已可见、已使用是三回事。** 第 51 题（CLM 时间线第 54、63、72 行，下一次网络请求 00004 回执）移出上一任务的工具批次，但保留更早的无关笔记。第 54 题（CLM 时间线第 60、75、87 行，下一次网络请求 00005 回执）移出另一旧批次并更换笔记。后续工具确实回显新笔记（如第 55 题第 72、110 行），但第 55 题末尾核验（第 202、217 行）没有展示笔记建议的语义级检查。源任务有效的做法不一定会迁移。
- **编辑回执不是性能测量。** 第 1、51、54 题回执记录投影体积从 144,706→102,601、288,762→283,774、451,936→436,774 字节。第 54 题的移除数 5 是该投影中与第 51 题合计，本次选择的批次有 2 项。这些不是 token、时延或计费降幅。审阅记录共 3 次主动编辑获接受、CLM 侧另有 7 次原生保护压缩、原生侧 3 次自动压缩；部分保护发生在恢复尝试，不属于被最终计分的本题执行。不要混计。

## 写法参考

- [Agent Skills 规范](https://agentskills.io/specification)和 [OpenAI 的技能编写示例](https://github.com/openai/codex/blob/main/codex-rs/skills/src/assets/samples/skill-creator/SKILL.md)：明确触发边界、只保留能指导行动的内容，研究材料不进运行时。
- [Anthropic：智能体记忆的组成](https://www.anthropic.com/research/components-of-agent-memory)与[长程 Agent 工程](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents)：区分原始记录、可恢复笔记和活动上下文，续跑时靠核验外部证据而非只信摘要。
- [面向任务的记忆效用](https://arxiv.org/html/2611.03930v1)与 [CompactionBench](https://www.microsoft.com/en-us/research/wp-content/uploads/2026/10/CompactionBench_preprint.pdf)：看记忆是否影响后续实际任务，压缩、缓存与恢复成本分开记账。
- [OpenAI 技能评估指南](https://developers.openai.com/blog/eval-skills)与 [The Resolution Hypothesis](https://arxiv.org/html/2611.23068v1)：既查过程也查产物，用留出任务和复跑判断是否值得留下一个版本。上述来源均未验证本仓库这两篇候选。

## 后续验证方案（未运行）

1. 在各自框架内固定模型、运行器版本、预算和评测标准。无技能与有技能对照，在未见场景上重复多个序列。至少覆盖短任务不应触发、强制中断、过期路径/版本、冲突笔记、缺回执，以及 CLM 的受保护片段或编辑拒绝。写技能时不看留出任务；不同时装两个语言版本或两种框架技能。
2. 任务结果和过程分开打分：是否只在适用时触发；关键条件是否原样保留；续跑环境能否访问定位；旧规则是否误导行动；官方回执的目标和版本是否匹配；编辑状态与后续投影是否一致。无评分的失败和重试也记录。另记总输入、可观测的缓存/未缓存 token、时延、恢复与重复工作。省掉无关文字不能与丢失未决动作、违反硬约束等量齐观。
3. 桌面检查通过只能说明说明书格式或流程可用，不是提分证据。先冻结验收标准，再按序列报告结果及变异。每次修订标注失败行为、修改规则与可以否证它的反例。

## 对技能文字做的桌面检查

| 场景 | 按说明应如何决定 |
|---|---|
| 短而独立的问题 | 不写笔记，不编辑历史。 |
| 压缩后恢复；旧笔记写“已完成”，但无回执 | 先核验当前目标及回执再重试；无法确认则标为未核验。 |
| 新证据与旧记录冲突，但来自另一版本 | 分开保留作用域，采纳当前版本的记录；不能裁决则记录复查条件。 |
| CLM 编辑入队后即时状态仍旧 | 不记为接受，检查下一次可应用请求。 |
| 编辑器拟删除体积很大、不可找回的唯一回执 | 留在活动上下文；无法恢复就不做有损删除。 |
| 旧笔记回显，但没有执行它建议的验证 | 记为可见，不记为已采用或有效。 |

这些是人工检查文字能否指导决策，未在真实 agent 上运行。
