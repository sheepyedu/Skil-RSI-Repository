# 做一次小而可验证的上下文编辑

只在有真实编辑接口时使用。没有接口时，如需恢复则保存可回读的交接信息，由运行框架管理原生会话。不要改写原始日志，也不要自行改变外部控制器规定的整理频次。

| 当前情况 | 做法 |
|---|---|
| 任务未结束，或工具结果、外部操作尚未核实 | 保持任务状态，不做非紧急整理。若容量即将阻断工作，先留检查点，再做最小、可恢复的编辑。 |
| 控制器已验收，过多的已完成记录干扰或挤占下一任务 | 读取一次有针对性的状态，明确下一步决策，只编辑不再需要的内容。 |
| 没有安全候选，没有验证过的恢复路径，或没有可观察的压力或收益 | 跳过。若控制器强制编辑，说明冲突，不为凑次数删除仍有用的证据。 |

## 保住下一步决策真正需要的内容

保留当前约束、未完成动作、外部操作回执和不可重建的精确证据。未结案的工具调用与结果不拆开。可能再次需要的大段证据，用获准且可读的定位符保存实体和版本；先验证能恢复，再从活跃上下文移除。已完成的噪声直接省略，不要重写成流水账。

只有后来可能用得上时才写短记忆。条目优先写成 **作用域与版本 → 已核实的事实或约束 → 证据位置 → 到期或失效条件**。区分未完成、尝试过、已验证。不要把旧任务里的事实提升为全局默认。不知道下一任务时，只保留可复用且有证据的检查方法及尚未结束的状态，不逐题复述。

## 提交编辑后，到实际应用的请求核验

检查接口契约、版本、计量单位、受保护内容，以及笔记是替换还是追加。读取结构化状态字段，不依赖截断的输出前缀。用新鲜 ID 提交一次范围明确的编辑。入队或工具说成功不算生效。查看实际应用请求或可信的投影回执，核对版本、移除内容和模型收到的内容。恢复后先校验关键状态或证据定位符，再做实质动作。原始与投影请求的字节数、服务商输入、缓存命中和输出 token 分开记录。

若编辑被拒，定位具体原因，刷新状态，安全时最多再试一次。若无法核验投影或关键状态缺失，停止删减并恢复或回读。无关的新任务先读自己的需求和环境，不盲用旧笔记。

## 用反馈修订，不把偶然经验写成硬规则

按作用域和版本检索，用时复核容易变化的事实。新证据推翻旧记忆时替换活跃条目并保留出处；仅不适用于当前任务时跳过或归档；冲突未决时保留两种说法，做最小区分检查。只有后续可核验动作确实受益，或受控重放支持时，才把候选升级为常用规则。分开记录笔记可见、实际使用、采取动作和验证结果。只修订最弱的一环，不重写整套规则。只有开发或验证该 skill 时才读[测试用例](references/validation.md)。
