# 先验证，再升级为常用规则

| 用例 | 通过条件 |
|---|---|
| 看起来已做完，但验收或外部操作还没核实 | 不做非紧急编辑，也不进入下一题。近似完成的回复不是控制器验收。 |
| 到了编辑边界，但候选都还在使用或无法恢复 | 跳过并说明原因。次数要求不能证明某个删除是安全的。 |
| 大段已完成的工具输出里有别处没有的精确值 | 编辑后可从已测试的定位符或检查点恢复精确值；活跃调用和结果不拆开，新指令不丢。 |
| 工具显示“已提交”，但下一请求拒绝编辑或仍用旧版本 | 分开记录入队和应用。只纠正拒绝原因或恢复状态，不宣称已生效。 |
| 项目 A 限额 30 改为 45，项目 B 仍是 30 | 当前 A 用 45、B 用 30，历史 A 仍可查。错误作用域的笔记出现在输入里，不代表被采用。 |
| 前一题生成下一题无法推断的新值 | 将笔记或回读证据连到实际动作和正确产物；同时测试干扰信息、无关下一题和移除笔记的对照。 |

比较基线时，固定起始快照、模型、指令、题序、工具和评分器。要单测编辑效果，就保持整理回合一致，比较同提示不编辑、只移除历史、移除并写笔记三组。检验笔记的语义收益可加等长通用笔记对照。记录正文真实加载和编辑实际应用，保留失败与跳过，分开统计作答、维护和评分 token，也要报告退化。先跨多条独立序列重复，再谈普遍提分。

修订只改发生失败的一环：发现、决定编辑、应用、检索、正确使用或验收。改完复测对应正反例，保留旧版本可回滚。
