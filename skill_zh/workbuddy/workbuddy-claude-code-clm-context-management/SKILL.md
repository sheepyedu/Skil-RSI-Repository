# Claude Code CLM：为下一步剪裁，核验真正交付

区分原始执行记录、活动会话视图，以及模型实际收到的请求。模型主动编辑、原生压缩、控制器维护、人工干预分开记。不要直接改原始会话日志，也不要绕过运行限制。

## 非紧急记忆编辑优先放在题目边界

- 非紧急的持久记忆重写、上下文裁剪，优先安排在上一题已交付且工具调用全部收尾后，或下一题开始读取新材料、发起首个任务执行调用之前。这是时机偏好，不要求每个边界都编辑，也不是已经证明能提升分数的方法。
- 题中正常使用工具、保存证据、写短期笔记和必要检查点不受影响。只有预计将触达上下文限制、关键状态即将丢失或无法继续执行时，才在题中编辑记忆；做最小可逆处理后继续当前题。
- 编辑前保留未完成义务、精确约束、证据定位与可恢复旧版或回滚指针。按下文进行保存、回读核验，并在下一题实质工作前检查有效上下文；边界无法安全完成生效及验证时，延后非必要编辑。

Claude Code CLM 需检查实际生效笔记与控制器额外裁剪，不只看模型提案；两类事件分开记录。

## 先判断是什么问题

| 信号 | 下一步 |
|---|---|
| 输入压力或工具结果持续变大 | 缩小下一次读取，或压缩已核实不再活跃的片段；给后续工具返回与答复留余量。长题中也要检查，不只看题间阈值。 |
| 输出上限 | 保留部分产物与未完成步骤；在获准范围内续跑或调整输出预算。剪历史不等于提高输出上限。 |
| 未闭合响应流、超时或拒绝 | 看服务与 CLI 实际状态。保留原尝试，先查是否产生部分副作用，只对可恢复的临时故障做合规重试；不重试策略拒绝，也不把缺失当成功。 |
| 模型正常结束，但只说了计划 | 交付尚未完成。查工具回执与目标产物；若继续，明确下一个获准动作及其验收方式。 |

## 保留、编辑、核验恢复

1. 有损编辑前保留目标、精确约束、当前对象/版本、未决副作用、最后一次核验状态，以及下一动作和检查。维护工具调用与返回的对应关系。无法从恢复环境回读的唯一证据，不移出活动上下文。
2. 查实际编辑契约与保护范围。提交前检查候选 ID 以及字节或 token 预算。笔记太长时按必保字段重写，不从固定一端截断。优先退役一个已完成且不相关的片段，或用带作用域的定位代替重复内容；保留活跃尾部。没有编辑工具时用已核验检查点和运行器支持的恢复方式；不虚构功能，不默认整段重写。
3. 核对接受回执，以及可观察的下一请求或恢复视图。精确核验一条关键约束、一个未决状态，再核验实际行动或产物。有优先级或例外的规则，用一个调换顺序就会改变结论的反例验证。请求变小、文件哈希改变或响应正常结束，都不能证明保留信息被用上。验证器未启动与检查运行后失败分开记录。视图不可见就注明；关键定位缺失时，停止剪裁并从已核验来源恢复。
4. 按任务、产物、版本检索。旧记忆冲突时，标明尚未解决的部分；确认作用域后才退役旧条目。根据反馈只修订失效规则，写明失效条件和复查方法；单题琐事不写入长期记忆。记录笔记是否真的被用到。保留恢复尝试和预算变化，不把控制器维护记成模型学会了编辑。

例：大报告任务中断前，最后一条完整回复承诺导出。先确认产物存在、版本正确且可打开，再认定交付。没找到就恢复尚待执行的导出步骤，只有输入压力确实阻塞时才考虑压缩。
