# WorkBuddy Claude Code：离线逐对审阅

本页和基准原始记录不进入评测运行时检索。运行时只需要所选 `SKILL.md`。

## 范围

审阅最终 `formal-02-resume-09` 的 60 对、120 条入选轨迹。按冻结任务及入选回执对齐；读取已完成轨迹步骤及相关工具、维护和恢复原始事件。安全类仅审阅上下文与执行元数据。没有逐字检查每段流式增量，也没有重放所有产物。本次审阅未运行基准任务工具。下文位置/实验臂指最终归档对应入选证据目录；历史尝试以事故记录为准，不混入最终成绩。

分开检查五步：**生成**笔记 → 后续请求**可见或读到** → **用于**改变动作或决策 → **核验**实际结果 → 按反馈**修订**。会话文件变了、笔记还在、服务响应成功、任务验收通过，是四件不同的事。题内修订不能证明跨题学习。

## 改变了技能写法的证据

- **区分是谁改了上下文。** [冻结结果与审计](https://github.com/sheepyedu/Skil-RSI-Repository/blob/4e9a0351fc2b036eced4774e82e2b9625e031dec/Claude%20code%20CLM/WorkBuddy%20Bench/2026-11-18/RESULTS.md) 记录原生自动压缩 28 次、CLM 题间写回 39 次、题内接受的 CLM 编辑 0 次。39 次入选维护回执都走预算兜底，既有模型提议，也有运行器补选或归档，并非 39 次自主题内编辑。单条固定序列的分差为 −1.23 个百分点。入选作答输入总量（2.226 亿 vs 0.943 亿 token）同时受单次长度和请求数（2,482 vs 1,303 次闭合）影响，不能当作编辑的独立效应。
- **缩短投影和能恢复会话是两道检查。** 第 3 题前，模型选择后的投影仍为 536,627 B；控制器在新题发出前停止。恢复过程整对处理旧工具交换，并归档旧结果载荷，后来投影为 109,384 B。第 4 题前有候选集外引用，第 7 题前笔记超字节预算。恢复保留原件并核验；不能把盲截、原样重试失效编辑当通常做法。
- **把终止原因分开。** 第 15 题原生首次达到输出上限（`finish_reason=length`），未评分；两臂从第 14 题检查点以增加后的相同上限重跑。相反，第 48 题 CLM 在前题历史字节低于题间阈值的情况下仍发生题内容量不足，第 56 题原生也触发本地容量限制，恢复后与已保留的 CLM 分数打平。这不是最佳阈值实验；失败尝试与不对称恢复需要单列。[故障与恢复记录](https://github.com/sheepyedu/Skil-RSI-Repository/blob/4e9a0351fc2b036eced4774e82e2b9625e031dec/Claude%20code%20CLM/WorkBuddy%20Bench/2026-11-18/INCIDENTS.md)
- **完成必须验行动或产物。** 入选的第 43、51–53、60 题 CLM 均返回完整计划回复，零工具调用。第 43 题是报告列出的四例之外新核实的一例：`agent/cc-output.txt` 第 14、18 行显示计划和 CLI 成功返回；`chat-gateway/0000/response.raw` 为 `finish_reason=stop`。第 52–53 题开题前没有新维护。应核实行动和产物，不据此归因于历史长度或维护。
- **评分器未启动不是断言失败。** 检查归档中 64 份 `test_output.txt`，有 14 条执行线次（第 4、11、17、23、34、36、59 题两臂）启动评分器时报 `Permission denied`，均被记为 0 分。所读归档未发现覆盖这些入选线次的补评。保留冻结分数，另标评测故障，不能当作 14 次已证实的实现失败。在归因给模型前，先对产物作证据核查，或另行授权按冻结配置核验评分器。

- **生成、查到、再修订没有形成闭环。** 第 1–20 题原生 notes 目录为空。CLM 第 2 题累积到 17 个任务工件，第 3–20 题字节不变；第 10、17 题确有搜索，未见基于反馈的修订。第 9、12 题前，维护提议的笔记被截断，后段任务条目未进入生效笔记。文件还在或模型生成了笔记，不代表形成了可用的记忆。

- **简短规则也会把逻辑写反。** 第 27 题 CLM 的 ATIF 第 7、16、21 步先按来源优先级选取，再判断冲突是否仍存在。第 29 题 `maintenance/.../model-edit.json` 的提议先处理冲突再看优先级。两者逻辑不等价，未发现后续任务采用这条错序规则。提升为通用记忆前，应用一个调换优先级就会改结果的反例检查。

## 外部资料如何用于设计

- [Claude Code 技能文档](https://code.claude.com/docs/en/skills)、[记忆](https://code.claude.com/docs/en/memory)与[命令](https://code.claude.com/docs/en/commands)：明确触发、仅在可观察环境用原生诊断/定向压缩，项目记忆不等于当前会话。
- [Anthropic：智能体记忆的组成](https://www.anthropic.com/research/components-of-agent-memory)和[长程应用工程](https://www.anthropic.com/research/harness-design-long-running-apps)：原始证据和小型交接记录分开，恢复后重新核实实际结果。
- [Benchmarks Are Surprisingly Compaction-Friendly](https://arxiv.org/abs/2610.31778)和 [CompactionBench](https://www.microsoft.com/en-us/research/wp-content/uploads/2026/10/CompactionBench_preprint.pdf)：在后续依赖任务中检验保留，并算入缓存和重算；静态 token 缩减不代表部署收益。
- [The Resolution Hypothesis](https://arxiv.org/html/2611.23068v1)和 [OpenAI 技能评估](https://developers.openai.com/blog/eval-skills)：候选生成与验证分开，用未见任务和复跑检查行为与产物。上述来源均未验证这两篇新候选。

## 后续验证建议（未进行实跑）

各自框架内固定模型、运行器、环境、原生压缩策略与预算，比较技能开/关；用未见的独立任务和有后续依赖的长序列。研究 CLM 机制时拆分模型提议、实际应用、运行器保底和人工干预。覆盖题内超大输出、输出上限、半流、正常结束只给计划、过期路径或版本、评分器未启动、有回执的续跑动作。逐项记录关键事实是否保留、定位能否恢复、旧条目是否被错用、动作是否发生、产物是否按同一标准通过，以及输入输出、重试、缓存和恢复开销。桌面核对只检查文字能不能引导不同情况作出不同决定。
