# 压缩效果与任务结果分开验证

## 适用与证据边界

适用于本仓库 Codex CLM 的 clm-context 接口，不适用于未安装该网关的原生 Codex。这是轨迹生成的候选skill，尚未独立验证提升。只读取当前任务允许的数据，不从评测答案或评分隐藏状态生成记忆。

## 反馈与修订

记录触发次数、执行开销、后续实际读取、恢复失败及当前任务结果。发现反例时保留原规则版本与来源，修订条件而非用一个结果推翻所有历史。与无skill/冻结旧skill多种子对照；把最终reward、记忆机制指标和费用分开报告。

## 触发条件

选择/修订压缩策略、声称成本或成功率改进时。

## 执行过程

1. 记录每次edit revision、drop组、当前任务、接受状态、原始请求大小与投影后大小；明确是累计值还是本次边际值。
2. 为压缩定义恢复检查：关键事实可取回、当前义务未丢、实体/版本未混、下游是否真的引用。
3. 记录模型当时可见的 observed_feedback 与事后 audit_reward，标出指标定义、范围和时间，不混用 Composite 与最终官方结果。
4. 分开报告总输入、缓存输入、未缓存输入、输出、工具调用与延迟，不能把输入减少直接叫费用或速度降低。
5. 对失败回溯编辑前是否已有错误假设、反馈是否可见、信息是否实际丢失，再讨论压缩因果。
6. 对候选skill做冻结版本、留出任务和相同顺序/多种子对照；显式记录无编辑反事实缺失。

## 停止条件与保护

运行新付费测试须沿用用户明确预算与账户权限，不能擅自追加高成本实验。

## 证据
对应事件：CX-C3、CX-C5、CX-C7。详见 [事件与证据](../../EVIDENCE.md)。

## 反例和失败信号

仅凭成功率53/54给定论；把100相依题当独立重复；用原始减累计投影当单次压缩收益。

## 回滚与权限
保留变更前的记忆版本及证据索引；新规则与当前工具事实冲突时先暂停新规则，从有来源的记录恢复。不恢复已确认过期的任务状态。没有恢复依据则标为未知，不伪造。技能不扩展外部动作授权。
