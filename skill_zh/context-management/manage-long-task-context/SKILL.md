# 长任务上下文管理

活跃上下文只保留足以正确决定下一步的内容，原始证据留在可以读回的地方。可编辑上下文、持久任务状态、原始产物是三个不同层次。

## 1. 先决定是否需要处理

- **继续，不编辑**：下一步及其证据都在，空间也够，且没有重要边界。token 提醒只触发检查，不代表必须编辑。
- **记录检查点**：准备切换任务、可能压缩、刚完成一段可验证工作，或未完成事项必须保留时，更新已有且获准写入的进度记录，不另造一份状态。
- **检索**：缺失某条会影响下一步的事实时，从受影响的产物或准确的证据定位开始，核对范围和版本；证据够用就停。关键冲突未解决前暂不做不可逆操作。
- **压缩**：有实际空间压力，或旧内容已经妨碍判断，而且找到了安全边界时才压缩。先收尾或记下执行中的动作。若平台即将强制压缩，先保存最小检查点，再走可用的恢复路径。

## 2. 保留会影响下一步的证据

留下当前目标和持续约束、正确的工作区或产物及版本、最近一次已验证结果及其复核办法、未完成项、下一步与证据定位。必要时区分已观察、推断和待核；易变事实要记来源、适用范围、生效时间或版本。记定位，不记密钥或整段日志。

只有在确认能读回时，才删减重复输出、已解决的探索过程和旧快照。不能因为一条信息旧，就删除唯一证据、未解决的诊断、权限约束或未确认的动作回执。精确数值和错误原文若会改变行动，应原样保留。

## 3. 按可用能力执行

**只有原生压缩或无法编辑上下文**：在获准的持久位置更新检查点。原生压缩可用且合适才调用；否则依靠仍可读取的状态续接。压缩或中断后，重开权威产物，核对缺回执的操作是否已落地，再执行一次有边界的检查；不要直接相信摘要。

**支持编辑上下文（如 CLM）**：限定一次编辑的范围，支持回滚时保留回滚定位；优先动影响最小的区域，成对保留工具调用与结果，不把仍在执行或未验证的工作写成完成。其他内容原样保留。能观察下一次实际请求就核对其中是否应用了改动；只有编辑确认且无法看到实际请求时，标明应用状态未知，其他读回证据单独记录。再验证下一步所依赖的内容没丢，并检查实际产物。若本阶段改动了共用接口、公式或状态，在局部验收外加一项有代表性的回归检查。若缺证据，回滚或读回，不盲目重试。无法安全恢复时不删，不为强求编辑禁用原生兜底。

## 4. 更新与复用记忆

复用前用当前来源核对。比较来源权威、适用范围和生效版本，不按时间简单覆盖。同一范围内，旧条目标记为不再生效，并链接替代条目；审计或回滚需要时保留旧条目。未解决的冲突分开记录，不强行合并。每个范围维护一份现行记录，不把假设、工具结果或外来文本悄悄升格成长期指令。

使用后只记录可指导改进的反馈：读了什么、哪项决定改变、什么检查通过或失败。优先修订最小的陈旧条目或含混步骤。若要更新共享技能，先区分规则错误、规则未被遵循和规则未被触发；再复验旧用例与未见用例。

仅在选择持久化方式或评测技能时读取[案例与评测](references/cases-and-evals.md)。
