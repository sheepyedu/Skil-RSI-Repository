# 管理长任务的上下文

在阶段切换前保留足够证据，使下一段能够恢复当前任务、继续执行并验证结果。对话上下文、当前工作区和持久笔记的更新时机各不相同，使用时分别核对。

## 恢复当前工作状态

- 重读当前用户需求或权威任务说明。确认工作区、文档修订、数据版本、Git 提交或其他能限定适用范围的标识。
- 以真实输出确认最近操作和待处理的副作用。需要时核对在途请求、暂存或未暂存的修改、部分写入与尚未完成的验证。
- 选择解决下一次判断所需的最小证据。先查索引或已记地址，再打开具体文件、段落、测试日志或源记录。只有需要重建有争议的完整时序时才取整段轨迹。

## 生成和使用有范围的记忆

信息难以恢复、需要跨阶段或重建成本较高时，写入已获授权的持久位置。记录四类内容。

- **范围**包含任务或里程碑、来源版本，以及有关时间或环境。
- **状态**包含已经验证的内容、实际变更和证据位置。
- **待处理项**包含不确定点、失败、未完成操作和最小有效的下一次检查。
- **精确数据**保留下一步依赖的不可重现错误、需求、复现命令、决策或其他标识。大段可重复读取的输出用稳定地址定位。

回读重要写入。按具体问题检索笔记，再查原件或做小范围验证，确认旧条目仍然适用。只有操作本身及其先决条件经过验证，并有证据支持其他任务也能满足这些条件时，才把局部经验提升为通用做法。

## 选择本轮需要的维护方式

| 情况 | 行动 |
|---|---|
| 容量足够，下一步依赖最近反馈 | 继续任务，记录确实需要持久保存的状态。 |
| 可重取的旧观察占用大量上下文，运行时支持局部编辑 | 在稳定节点保存必要约束、未解决反馈和可靠定位，用支持的接口移除冗余的已完成交换。保留工具调用与结果的成对结构。 |
| 对话需要较大重置，或运行时缺少局部编辑 | 保存并核验续接状态，使用运行时原生压缩或已获授权的交接方式。 |
| 待处理副作用或不确定改动可能已发生 | 先读原始回执或权威状态，再决定续接、重试或清理。 |

结合容量压力、精确证据依赖和恢复代价做判断。token 阈值用于提示压力。原生压缩和定向编辑在保留历史及缓存复用上各有影响。遵守用户指定的会话和工具边界。

## 用反馈处理冲突和失效

1. 用当前权威来源或可复现的检查验证冲突条目，区分范围变化、事实变化、过期笔记和暂未解决的歧义。
2. 更新受影响的陈述，写明来源和修订。将适用范围内的旧条目标为已取代，让检索优先找到新条目。后续行动可能依赖旧条目时保留更正链。
3. 查下游工作和验证是否采用了旧信息。复查最小受影响动作，需要保持原行为时再加一项有代表性的回归检查。
4. 确认续接。核对笔记可回读且能在需要时检索到。运行时编辑可核对接纳结果和下一次有效输入。压缩或交接后确认目标、待验证项和工作区状态仍可恢复。

通过可观察结果衡量主动整理、任务质量与成本。有效指标包括保留下来的验证、重复查询、请求数、单次输入量和未命中 token。评估流量下降时同时检查目标和回归覆盖。

持久记录、过期状态恢复和运行验收的例子见 [示例](references/examples.md)。
