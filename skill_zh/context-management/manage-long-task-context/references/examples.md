# 工作状态示例

## 小型续接记录

已有进度文件或记忆库时沿用原位置。可以按以下方式记录。

| 字段 | 示例 |
|---|---|
| 范围 | 导出任务、预发布环境、数据结构修订 18、本次批次 ID |
| 已验证和已变更 | 小批量导出行数与来源一致，见清单和校验和。大批量导出仍在途。 |
| 证据定位 | 清单路径、日志位置、请求 ID。原日志即将失效时保留必要的原始错误行。 |
| 待处理 | 查询现有大批量导出请求。客户端超时后服务端状态仍不确定。 |
| 下一次检查 | 核对完成回执和行数，再判断是否需要重试。 |

工作状态增加时只在活跃索引中保留少量当前条目，细节放在稳定指针后。将陈述标记为已验证、暂定或已取代，并记录新条目起效的修订。

## 编辑前判断需要查回什么

长时间排障留下十份相同构建日志、一份由测试配置变更引起的错误，以及一个在途异步测试。保留测试配置、相关错误行和日志地址、在途请求标识。先核对在途测试，再在稳定节点清理重复日志。可读到下一次有效输入时核对预期变化，条件允许时复跑最小行为检查。

一条观察只有一份副本且即将失效时，复制必要摘录或继续留在工作上下文。原始内容即使占用很大，仍按恢复代价和当前相关性决定是否保留。

## 修正过期结论

报告使用过一条笔记，称样本排除兼职人员。交接时数据字典显示该限制从修订 7 起取消。核对每张表实际使用的版本。旧定义保留在早期修订范围内，从修订 7 开始标记为已取代。改正受影响的表，用新筛选条件复核分母，并让索引指向当前定义。短小、有范围和来源的更正便于下一次检索。

## 验证 skill 有没有帮助

选用有明确来源证据、并且续接结果可观察的情形。可以覆盖可重新获取的大结果、状态不明的在途操作、权威来源版本变化，以及只支持原生压缩的工作流。

在相同任务与起点比较原工作流和使用 skill 的工作流。记录下一步是否查回正确证据、保住待处理事项，并完成有实际意义的目标和回归检查。另记重复查询、请求次数、缓存未命中和已确认边界前后的字节或 token。编辑影响之后的工具调用或成本时，同时观察即时投影和后续行为。既检查需要维护的情况，也检查继续做任务更合适的情况。
