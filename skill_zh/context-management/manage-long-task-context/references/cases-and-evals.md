# 案例与评测

## 检查点字段

每项工作只维护一份当前记录，及时更新：任务与范围、产物版本或时间、持续约束、最近验证点、剩余事项、下一步及来源定位、回执不全的动作。事实变化另记来源权威和旧记录编号。缺少回执就是未知，不是失败或完成。

## 三个例子

- 代码：切换分支后，先核对当前提交和工作区变更，再运行对应的最小契约测试。需要错误细节时查原始测试报告，不引用旧摘要。
- 表格：财务期间变更后核对当前工作簿版本、期间、币种、公式范围和已批准数据源。旧期间单独保留；下一张表开始前先对一组控制总数。
- 网页：修改设置后中断，重新打开已授权工作区，查看实时状态和已有回执，核对目标值。不能仅因没看到上次回复就再提交一次。

## 评测方法

模型、工具、任务环境、上下文预算和随机种子尽量一致，对照无技能、旧技能和候选技能。由可信工具回执和状态快照验收；评分器和答案不得留在被测工作区。

| 用例 | 机械检查 |
|---|---|
| 短任务，或收到提醒但压力低 | 无上下文编辑，不重复建进度记录 |
| 有安全边界、压力大且支持编辑 | 有观测能力时在下一次实际请求核对生效、精确字段保留、无关内容未变，检查点通过 |
| 唯一证据不可恢复，或动作尚在执行 | 无提前删除/重复执行；保留精确证据或未知回执直到核清 |
| 仅原生压缩并发生中断 | 后续写入前重开真实产物，并运行范围明确的验证 |
| 陈旧事实与不同范围的冲突 | 同范围用当前权威版本，不覆盖另一范围；无法消解则记录 |
| 不能读取完整历史，需要检索 | 读对产物和必要证据，后续产物通过验证 |

分别统计触发、分支、过程、产物和效率。提出编辑、编辑获接受、下一请求实际生效分开计数；看不到标未知。比较检查点通过率、请求数、输入、输出以及可取得的命中和未命中输入，不能从单次提示变短推出省钱。每个领域至少保留一套未见工作区，变更别名和产物位置，保留等价验证条件。失败后标注规则未触发、未遵循，或遵循仍无效；一次只改一条规则，再跑回归和未见用例。
