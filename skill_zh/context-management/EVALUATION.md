# 技能生成、使用、反馈和修订的验证协议

1. 冻结本包版本，预登记要改进的机制，不将500执行当500独立样本；发现数据不能又充当独立验证集。
2. 先做边界回放：还原编辑前任务环境、预算、可见上下文与持久文件，比较无技能/旧技能/候选技能。验证状态恢复、来源可追溯、作用域、误删恢复和实际使用，不先追求得分。
3. 再做完整长序列：固定模型、推理设置、窗口、维护阈值、重试/恢复和工具版本。比较同序、乱序与留出任务/种子，多次独立重复。长序列为实验单位，不能将相依100题当独立重复。
4. 主指标是官方结果；分开记录事实保留率、未提交误报、重复动作、冲突撤销、跨题回读、工具开销、总/缓存/未缓存输入、输出及维护耗时。报告即时可见反馈与审计reward的口径。
5. 对CLM记录queued/accepted/rejected、revision、实际下一请求投影和可恢复性；原始减投影是累计效应，不能累加作单次节省。字节不是token，未实现SCR就不讨论KV复用收益。
6. 防止评测捷径：运行时技能不携带本批答案、未来git修复、预注入隐藏测试或评分隐藏状态。研究证据与被测技能物理分离。
7. 反馈形成变更单：规则版本、触发事件、旧条件、新条件、反例、验证结果。候选→有限验证→推广；失败则暂停/收窄并恢复上一有效版本，不不断追加矛盾提示。

本包未执行新增付费测试，未安装或改变用户现有运行器。单个Markdown技能不是已实施的harness门控。新测试须先确认计算资源、费用边界与允许的实验动作。
