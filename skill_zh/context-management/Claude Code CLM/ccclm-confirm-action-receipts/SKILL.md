# 完成状态只接受工具回执

适用：Claude Code CLM。状态：轨迹归纳的候选技能，尚未做独立干预验证，不能承诺提分。只使用当前任务允许的信息，不把评测答案或未来提交写进技能。

## 触发
在任务总结、记忆写入完成事实或 stop/status 提醒时使用。

## 生成与使用
1. 为关键动作区分 planned、submitted、confirmed，并绑定 task_id 与动作ID。
2. 仅以匹配当前任务的实际工具结果升级 confirmed；叙述“已经执行”不能代替 benchmark.act。
3. 写任务结果前先核对 status/最后回执；Write/Edit 是否成功与任务动作是否成功分别记录。
4. 若 status 显示未完成，按当前协议执行剩余动作，不重复已确认的副作用。
5. 若同一错误在提醒后复发，提出运行器级完成门控需求；未实现门控前不能说提示词已解决。

## 反馈与修订
统计提前完成声明、遗漏动作和误记成功；不要用任务输赢评价回执门控是否正确。 保存变更前版本、证据来源和适用条件；发现反例先收窄或暂停规则，再验证新版本。不要将一次任务成功当成技能有效的证明。

## 边界与回滚
工具无状态查询时保留 unknown，先读取可得回执；不要为了验证而重发不可幂等动作。 记忆写入失败时保留旧版，不把计划当作成功；恢复只能依据可读取的证据，不能凭印象补全。技能不扩展工具权限或外部动作授权。

## 证据
CCLM-E2；q75、q86、q96。 参见 [事件与证据](../../EVIDENCE.md) 和 [验证方案](../../EVALUATION.md)。
