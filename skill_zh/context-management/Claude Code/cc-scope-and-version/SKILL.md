# 为实体与环境建立记忆作用域

适用：Claude Code 原生长会话，使用其现有 Read/Grep/Write/Edit 与持久notes，不依赖CIM。
状态：来自离线轨迹审阅的候选skill，尚未验证提分。

## 触发
切换对手、仓库、数据库实例、任务家族，或同名字段出现不同语义。

## 执行流程：生成 → 使用 → 反馈 → 修订
生成：每条记忆绑定family、entity、schema/version、观察时间、证据路径；把方法与实例答案分开。
使用：新任务先核对当前实体、schema、单位、预算和工具协议。迁移方法；数字/字段解释只有匹配作用域并复查后才迁移。不使用“同一个列名必然同单位”的捷径。
反馈：相反证据先检查对象/版本是否变化；不要把A的观察写入B profile。
修订：明确过期条件，保留旧版本证据并使旧规则退出active集合；不要把某一任务的回顾猜测写成已重跑验证。

## 证据
对应事件：CC-N5。详见 [事件与证据](../../EVIDENCE.md)。

## 验证
跨实体污染数、过期schema引用数、重新验证成本与收益。
使用同任务顺序的开关对照、多随机种子及未参与归纳的留出任务，不把本次原轨迹当新的泛化验证。

## 回滚与权限
保留变更前的记忆版本及证据索引；新规则与当前工具事实冲突时先暂停新规则，从有来源的记录恢复。不恢复已确认过期的任务状态。没有恢复依据则标为未知，不伪造。技能不扩展外部动作授权。
