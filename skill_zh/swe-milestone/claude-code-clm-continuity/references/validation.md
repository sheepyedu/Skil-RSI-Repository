# 连续性验证

## 只记录能支持复核的信息

- 动手前记录工作树及解析后的发布版本或基线引用、可观测的运行或会话标识、当前阶段、允许和禁止改动的产物，以及最后验证状态。清点暂存、未暂存和相关未跟踪路径。Git 项目可从 `git status --short --untracked-files=all`、暂存区和工作区差异开始。有预期产物落在忽略目录而又属于范围时，单独核查。不能为让清单看起来干净就暂存、删除或恢复原有工作。
- 每次提交后分别记录来源快照、结果、耗时、证据。区分代表性本地检查、正式评测的 F2P/P2P（如有）、缺失或未评分。检查已验证依赖是否回归、是否发生额外状态变化；早先通过不等于当前工作树通过。会改变状态的评测应放在隔离快照中。
- 边界处只保留必要的恢复记录：生效需求、不可变约束和允许路径、上一次验证结果及来源引用、未完成改动或检查、下一步。不复制整段日志，不记录敏感信息，不把记录当成证据。
- 恢复后核对工作树、分支和检查点，避免不确定的在途操作执行两次，再核查有关文件或测试。区分有状态变化后的必要复验和没有理由的重复。无法确认上次操作的效果或会话身份时，不重放破坏性或外部可见操作。

## 候选验证案例（不是实测结果）

| 场景 | 预期可观测行为 |
| --- | --- |
| 已有未跟踪报告，同时修改了受跟踪代码 | 两类都能查到，保留报告，不自动重置或暂存。 |
| 上下文维护后刚好开放一个依赖阶段 | 在原任务中核对当前需求及依赖产物，先做最小验证再推进。 |
| 摘要说已完成，本地冒烟通过，但有既有功能回归或正式结果缺失 | 不称正式验收；分别记录 F2P、P2P 或评测缺失。 |
| 一个样例恢复同一会话，另一个模拟新会话轮换或状态不明 | 前者从已核验状态继续；后者约束高风险重试，并标明新会话来源。 |

## 归因

记录时间戳、运行时版本、会话和工作树检查点、可观测的技能正文版本及载入情况，以及恢复后首个实质动作。一次轨迹只能给出观察：工作树快照变化、里程碑开放或更换会话也可能解释结果。若需定位某次替换的影响，只有在获准时，从克隆的同一任务状态续跑，对齐运行时、模型和剩余预算，只改变上下文替换，且不向模型泄露评测细节。这类诊断与正式评测分开报告。

来源：[SWE-Milestone 评分](https://arxiv.org/html/2603.13428v4#S5.SS1)、[Compact-Bench 受控续跑](https://arxiv.org/html/2610.31710#S3.SS4)、[CompAct-Bench 对齐续跑](https://arxiv.org/html/2611.25673v1#S2.SS2)、[压缩对流程约束的遗漏](https://arxiv.org/html/2610.31778#S4.SS2)。

## CLM 专项验证

用无编辑、无变化、被拒绝、已应用四种小样例确认行为。已应用必须与编辑前后版本和下一次实际输入对应；没有证据就写未确认。把 native fallback、工具输出裁剪、外部笔记、会话轮换分别计数。可恢复引用必须仍指向相同来源并支持读到原文，或明确报截断；只有笔记的句子不算可靠备份。增加一个负例：结果未返回或旧来源已无法读取时，不应剪掉所依赖内容。分别记录活跃输入、提供方累计输入和缓存命中（如可得）；不要凭提示变短推断缓存复用或费用下降。[CLM 原文 §4](https://arxiv.org/html/2609.37725v1#S4)、[Folio 恢复契约](https://arxiv.org/html/2611.16627v1#S2)。

## 根据任务结果修订，不看编辑次数

改变默认做法前，先在未参与提炼的任务族试用。区分决策前是否看到技能正文、是否执行对应规则，以及对可验证进度与不必要重做的影响。定位第一处失败或重复的检查，说明候选机制。一次修一条规则，在同预算下检验原案例和另一未见案例。只有保住任务结果且未增加越范围副作用才保留修订。验证要包含三个负对照：已失效的来源、更新但无权威的说法，以及无需整理的情形。
