# 可编辑上下文下的工程连续性

1. 先锁定范围：仓库和工作树、分支与 HEAD、当前需求、允许和禁止修改的路径，以及已有的暂存、未暂存和相关未跟踪内容。保护原有改动和工作状态。里程碑是同一工作的不同阶段。
2. 只用运行时明确支持的上下文控制。确认确有上下文压力时，优先找安全边界：关键状态已验证或可恢复，待返回的工具结果和生效不明的操作均不依赖这段文本。到达里程碑本身不触发编辑。没有安全且有价值的编辑就维持原样；达到硬上限时走运行时支持的兜底，不绕过上限。
3. 保留现行目标与约束、当前需求、最近验证的状态及来源、未解决的失败或假设，以及一项可执行下一步。先去冗余；有未解除的依赖，或原文无法找回时，保留精确信息。其余信息可保留稳定引用并标记截断。不要篡改上位指令，也不要拆开工具调用和对应结果。
4. 有运行时证据表明替换已进入下一次实际模型输入，才能说编辑已生效。区分已接受、拒绝、等待生效和无变化；外部笔记、普通工具输出裁剪、原生压缩和会话轮换要另记。不要杜撰编辑命令，也不要把上下文变化当成完成代码工作。
5. 恢复后核对会话和工作树身份、已跟踪与未跟踪改动及最新需求，执行相关的最小验证。区分新行为的由失败变通过（F2P）、回归检查的持续通过（P2P）、代表性本地检查和正式评测。状态不明先保全；仅在已授权协议允许时可新开会话，并单独标注。

**证据冲突时：**先核对来源权限和适用范围，不以最新记录自动覆盖旧记录。只更新被替代的事实，保留仍有效的范围。不要为了修复上下文直接改宿主会话文件、权限配置或评分器；走已授权的运行时入口。

编辑来源不明或需要比较编辑效果时，读[验证说明](references/validation.md)。本技能不是上下文编辑实现，不改变运行时权限。
