# 故障、恢复与验收

所有失败尝试保留原目录和原始证据。以下记录区分已观察现象、代码改动、恢复版本及测量限制。

| 阶段 | 现象 | 处理与实测 |
|---|---|---|
| 启动和镜像 | H20 的 Docker Hub 和 Debian 下载不稳定，首轮任务镜像构建未完成 | 从 Node01 缓存转移基础镜像并双端比对 SHA-256。使用官方 Debian 软件包安装独立的 Compose；调整 Debian 与 Python 下载镜像。复用经过核对的 Web 浏览器运行时镜像层，单独挂入题目工作区。正式镜像 ID 逐题固定。 |
| 记录器探针 | 初版请求处理和无有效事件时的 ATIF 转换中断 | 更名请求生命周期方法，修复空事件转换，保留原始 CLI 输出。独立会话通过实际 API 验证。 |
| 原生会话 ID | Harbor 会设置代理执行 ID，初版调用把它交给用于续接的 CLI | CLI UUID 使用独立字段。首题指定 UUID，后续同一 UUID 续接并核对实际 init、CLI 终态和保存的会话。 |
| `pilot-02` | Code 评分调用占位脚本，两组未找到 reward 文件 | 显式接入官方 CompositeVerifier，并保持 Security 原有程序评分。两条失败回执和修复后的官方评分均留档。 |
| `pilot-03`、`pilot-04` | CLM 到 Web 题时，CLI 在向 DeepSeek 发送请求前报 `Prompt is too long`。修复第一轮仅改写请求投影和续接副本，历史 token 计数依然挡住续接 | `pilot-05` 清理续接副本中的旧用量元数据，用相同 UUID 恢复。模型实际请求重新出现，原始 transcript 和用量不变。 |
| `formal-01` | 正式首题两组均在触发 API 前退出。早期题面传输会解释反引号 | 改成逐字传输。验收同时在投影后的 Claude 请求及真实 DeepSeek Chat 请求核对原题。旧结果按工程记录保留，正式使用重新验收出的 `formal-02`。 |
| `pilot-06` | Office 原生组等待 DeepSeek 超时，该尝试没有响应字节 | 保留全部回执。仅针对未收到任何响应字节的超时提供一次记录在案的同请求重试。用 `pilot-07` 从两条已验证的上一题检查点续跑，保留已成功的另一组结果。 |
| `pilot-07` | CLM Security 在题内发生本地容量失败，已有 24 个完整模型响应，最后成功请求为 178,946 输入 token | 将换题容量维护提前至 285,000 消息字节，目标 165,000 字节。CLM 本地续接窗口设为 393,216 token。恢复后首个实际请求 40,408 输入 token，保留前两题，`pilot-08` 成功评分并通过全部四类试跑。 |
| 会话同步探针 | 第一次续接在网关提交后没有继续执行 | 通过 SDK 流初始化新 CLI，打开中断轮次的自动续接，并确认原题出现一次、已完成工具没有重跑。两次探针的 stdout、失败记录及文件校验保留。 |
| 会话同步验证 | 网关投影与已加载的原生 CLI 内部状态可能不同步 | 新版本在安全的模型调用边界暂缓转发，终止独立 CLI 子进程，归档原 transcript，原子提交候选会话，再按同一 UUID 恢复。真实 DeepSeek 双题实验验证一次原生同步，下一次请求 HTTP 200，删去的工具交换、保留的题面及会话续接均被核对。此版本具有独立回执，正式 `formal-02` 启动后保持其原配置。 |

正式运行中的任务得分属于模型表现。执行或传输异常、真实题面偏差、评分缺失才影响运行验收。容量维护请求也是模型用量，后续汇总应单列。

## 正式第 3 题维护预算故障

CLM 的第 2 题最后实际消息历史为 1,638,246 字节。规则要求至少移除 1,476,246 字节，所有可整段移除的 58 次工具交换合计只有 1,256,415 字节。DeepSeek 维护请求返回 HTTP 200，共选中 18 段、1,103,061 字节。最初的维护方案投影仍占 536,627 字节，控制器在第 3 题 CLM 组发出题目请求前退出。原生组第 3 题已经完成，包含一次原生自动压缩，压缩后成功继续请求和评分。

恢复版先使用原模型选择和记忆笔记，然后为剩余的旧工具结果保留结构与工具调用 ID，并移除归档的旧结果载荷。若仅裁剪工具结果仍无法达到目标，程序按可回收字节大小补选已完成、已进入编辑候选的工具交换。原生会话保留非工具块和逐字匹配的历史 benchmark 用户题面，原始副本另外归档。回放预估和请求投影分别核对 165,000 字节目标，早先题目的产出原件继续由可访问的归档提供。

第一次离线修复仅裁剪结果，回放历史最小仍约 185 KB。随后版本补选了 3 组工具交换并裁剪 24 条已完成工具输出，实际输入快照离线复验通过，回放预估 164,844 字节，网关投影 109,384 字节。该复验没有新增 API 调用，保留两道历史题的题面与原 SHA-256。恢复目录有独立版本回执，可追溯变更首次应用的题序。 [停机观测](evidence/observation-2133-formal-02-stop.json) · [复验](evidence/formal-02-recovery-probe.json)

## 正式第 4 题维护引用校验

第 4 题原生组 52 次 DeepSeek 调用全部闭合并收到正式评分。第 4 题 CLM 的维护响应是合法 JSON，笔记是 1,200 UTF-8 字节，20 个选择里有两个不在供应给维护模型的候选表。旧校验器整体拒绝，并在该组开题前退出。因此这一异常出现在题间维护，没有产生第 4 题 CLM 题目请求。

第二次恢复只让模型选项与已验证的候选表相交，保留原响应和忽略项计数，继续核对投影预算和原生会话。原始快照离线验证复用 18 个有效选项，回放预估缩到 164,910 字节，保留前三题逐字题面。容量保护另补选 32 组旧工具交换并裁剪 7 条旧结果，回放与实际请求再次核对后才放行下一题。此时固定题单、两条会话 UUID、评分配置照用，控制器只首次派发第 4 题 CLM。 [异常观测](evidence/observation-2201-formal-02-resume-01-stop.json) · [离线复验](evidence/formal-02-recovery-02-probe.json) · [恢复代码](src/serial-recovery-02/)

## 第 4 题残留后台工具

第 4 题 CLM 在 34 次完整作答调用后已经写出成功终态，但 Claude Code 仍在等待任务容器内一个递归搜索后台子进程，官方评分尚未开始。操作前核对唯一目标容器、CLI 会话、子进程谱系和完整输出，在 22:17:59 只对该搜索进程发送 SIGTERM。CLI 接着完成 2 次模型调用，正常退出并进入原评分器。评分器给出 0/15，两组得分均为 0。

这是一次人工干预的有效评分试验。终止后台搜索后模型继续发出请求，所以后续分析把第 4 题 CLM 标记为人工干预，并保留干预前 CLI 流哈希与所有 36 次调用。第 5 题在四题独立验收后启动。 [处理回执](evidence/task-004-background-cleanup.json) · [完整四题核验](evidence/formal-first-four.json)
