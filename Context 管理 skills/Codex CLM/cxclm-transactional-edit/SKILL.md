# 事务式压缩与回读

## 适用与证据边界

适用于本仓库 Codex CLM 的 clm-context 接口，不适用于未安装该网关的原生 Codex。这是轨迹生成的候选skill，尚未独立验证提升。只读取当前任务允许的数据，不从评测答案或评分隐藏状态生成记忆。

## 反馈与修订

记录触发次数、执行开销、后续实际读取、恢复失败及当前任务结果。发现反例时保留原规则版本与来源，修订条件而非用一个结果推翻所有历史。与无skill/冻结旧skill多种子对照；把最终reward、记忆机制指标和费用分开报告。

## 触发条件

旧工具交换变长、已完成阶段可外置，且当前未完成义务已有状态记录时。

## 执行过程

1. 执行 `clm-context status`，读取revision、现有note及editable列表。按语义选旧交换，不按字节大小盲删。
2. 为候选交换保留任务/实体、来源、已完成动作、当前状态、未决问题、精确文件路径及恢复命令。精确值先存盘，用实际读取验证可恢复。
3. 必要时对候选调用 `clm-context show ID` 保存可见交换；注意show省略reasoning，因此不是完全无损备份。
4. 构造完整替换note，合并仍有效旧note；省略 `--note` 才表示保留。不得遗漏其他仍需保留领域的索引。
5. 提交 `clm-context edit --drop ID1 ID2 --note '...'`。多个ID以空格分隔（示例ID需替换为当前真实ID）。提交回执只表示排队；下一模型请求后执行status确认last_edit为accepted。拒绝时先重新读revision和候选，不能复用过期ID。
6. 抽取至少一个被删交换对应的关键事实，从文件重新读出并核对，再继续依赖它。成功后停止重复status轮询。

## 停止条件与保护

note上限8192 UTF-8字节，drop必须非空且投影严格缩小。用户/developer及最新完整工具组受保护，不尝试绕过。

## 证据
对应事件：CX-C1、CX-C5。详见 [事件与证据](../../EVIDENCE.md)。

## 反例和失败信号

仅有accepted、没有恢复测试；路径存在但无法解析；note替换遗漏旧领域；把累计before/after字节差误认为本次节省。

## 回滚与权限
保留变更前的记忆版本及证据索引；新规则与当前工具事实冲突时先暂停新规则，从有来源的记录恢复。不恢复已确认过期的任务状态。没有恢复依据则标为未知，不伪造。技能不扩展外部动作授权。
