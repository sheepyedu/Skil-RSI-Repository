# 有余量且有进展的容量维护

适用：Claude Code CLM。状态：轨迹归纳的候选技能，尚未做独立干预验证，不能承诺提分。只使用当前任务允许的信息，不把评测答案或未来提交写进技能。

## 触发
大结果工具调用前或运行器触发容量维护时使用。

## 生成与使用
1. 读取当前阶段窗口、输出预算和维护阈值；这些是运行器配置，不将历史120k阈值当通用常数。
2. 预留下一工具结果与回复空间；先保存当前状态，再选择可回收交换。
3. 小批 prune 后检查容量变化、accepted、事实可恢复性；不要无限 catalog 或重复维护回声。
4. 区分原始请求与投影、累计移除与本次边际移除；报告维护自身消耗。
5. 若主要占用来自不可删头部或用户历史，停止无效剪枝，报告容量下界并采用获准的安全恢复方案。

## 反馈与修订
将维护轮数、无进展退出、未缓存输入、输出和恢复质量一起记录，不只优化字节。 保存变更前版本、证据来源和适用条件；发现反例先收窄或暂停规则，再验证新版本。不要将一次任务成功当成技能有效的证明。

## 边界与回滚
后期 memory-only 回合由运行器阈值触发，不声称完全自主；JSON剪枝不是SCR或KV缓存复用。 记忆写入失败时保留旧版，不把计划当作成功；恢复只能依据可读取的证据，不能凭印象补全。技能不扩展工具权限或外部动作授权。

## 证据
CCLM-E6；40次accepted；多阶段配置见 EVIDENCE。 参见 [事件与证据](../../EVIDENCE.md) 和 [验证方案](../../EVALUATION.md)。
