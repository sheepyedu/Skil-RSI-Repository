# 先核验保存，再剪枝

适用：Claude Code CLM。状态：轨迹归纳的候选技能，尚未做独立干预验证，不能承诺提分。只使用当前任务允许的信息，不把评测答案或未来提交写进技能。

## 触发
在本仓库 Claude Code CLM 准备 prune 或容量维护前使用。

## 生成与使用
1. 先确认当前运行阶段与实际工具。后期使用 mcp__clm__catalog / mcp__clm__prune；原生 Claude Code 没有这些接口。不要用 Codex 的 clm-context 替代。
2. 从尚可见的工具结果生成恢复胶囊：task_id、环境版本、阶段、已确认动作、未决项、唯一新事实及来源。用持久工作区 Write/Edit 保存，再 Read 核对。
3. 调用当前 catalog；其仅返回 ID、bytes、tools，不提供内容预览。只删能与已保存事实或可重取内容建立明确对应的交换，不按体积盲删；映射不明则保留。
4. 按实际 schema 提交 drop，最多40个 ID；note 可选且最多4000字符；传入时完整替换，先合并仍有效旧 note 与其他领域索引，省略才保留已有 note。不要把提交当生效。
5. 在下一次 catalog/可用审计记录核对 accepted，并核对实际下一请求投影；普通模型不可见投影时记录该验证缺口。恢复至少一个被删交换的关键事实后再依赖它。

## 反馈与修订
记录保存成功率、事实恢复一致性、额外检索成本及拒绝原因。连续维护没有容量进展时停止重复调用，保留状态并转安全恢复。 保存变更前版本、证据来源和适用条件；发现反例先收窄或暂停规则，再验证新版本。不要将一次任务成功当成技能有效的证明。

## 边界与回滚
ID过期或参数失败时刷新 catalog；若误删且已生效，当前工具不承诺撤销 prune。通过持久证据回读恢复语义，必要时由运行器从快照恢复，不能声称已恢复原始上下文。 记忆写入失败时保留旧版，不把计划当作成功；恢复只能依据可读取的证据，不能凭印象补全。技能不扩展工具权限或外部动作授权。

## 证据
CCLM-E1、E6；q43，q93、q97。 参见 [事件与证据](../../EVIDENCE.md) 和 [验证方案](../../EVALUATION.md)。
